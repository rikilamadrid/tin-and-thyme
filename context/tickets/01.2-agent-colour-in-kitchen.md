### Implementation notes (worker 01.2, 2026-11-13)

- **One input per robot.** `agentColor(config)` in `src/galley/model.ts` is the only place a
  colour enters the kitchen: `AgentConfig.color`, lower-cased, or `null` for "the design's own".
  `CrewMember.color` carries it; the robot accent, the name tags, the roster chip and every
  portrait read that one field.
- **Native teams only.** `agentColor` returns `null` whenever the agent has `config.crew` (a
  Pathfinder session), so Pathfinder mode draws exactly as before. Whether a picked colour may
  override a character's designed accent there is still the human's decision; nothing is wired.
  The 14 variants ignore a colour in `drawRobot` and keep their `CREW_VARIANTS` accent.
- **The accent part per base design** (`ACCENT_PARTS` in `src/galley/robots.ts`, by part/detail
  index; nothing else in a design is recoloured): Basil toque band · Pepper headband and its
  knot · Roux pot band · Ember oven mitt · Sprig dome collar · Crumb apron · Mochi cap and its
  brim · Dash running lights · Pinch belly band · Crew bot chest panel.
- **Reserved and malformed colours** (`usableAccent`): a colour must be `#rrggbb` and not in
  `RESERVED_ACCENTS` (`#ff77a8`, and `#ff4f7b` = the scene's `ALERT`). Anything else is never
  drawn: the robot keeps its design accent and gets no tag strip and no roster chip. The check is
  inside `drawRobot` too, so no caller can paint a reserved pink. `AgentConfig.color` is a free
  string on the server (`updateAgent` stores up to 8000 characters), which is why the format is
  checked before it reaches a canvas.
  - Consequence: `agentPalette[0]` is `#ff77a8`, the default colour of every lead. A lead keeps
    Basil's own accent until another colour is picked. In Settings → Team the pink swatch is
    shown dimmed and disabled, and an agent whose stored colour can't be shown says so under the
    picker.
  - Not applied: the 09.1 rule that refuses the unknown grey `#c2c3c7` for a non-`unit`
    character (`crewColorProblem`). It is a Feature 09 crew-customization rule; this ticket's
    notes name the pinks only. `#c2c3c7` is the palette's "silver" and stays pickable.
- **Existing teams change on sight.** Every agent already has a stored colour (the palette, in
  order), and nothing distinguishes a default from a pick. So a native team's non-lead robots
  show their stored colour as soon as this ships (the second agent's `#29adff` headband, …).
  That is the Feature's requirement (`AgentConfig.color` drives the accent), not an opt-in.
- **Name tag** = a 2-unit colour strip down the left edge of the plate / floor tag / scanner tag /
  walking tag (`tagColor` in `src/galley/scene.ts`). The words stay light on dark whatever the
  colour. The walking tag is 3 units wider when it has a strip; no other tag changes size.
- **Roster chip** = a 10px colour square before the name on the crew card (`CrewPanel.tsx`).
- `src/galley/scene.ts`: besides the tags, `bot()` takes the accent and the six crew draw sites
  call `crewBot(B, member, …)`. The robot's accent cannot reach the kitchen otherwise. No layout,
  placement or `spriteBase` change.
- One file outside the ticket's list: `src/ui/drawers/CrewHeader.tsx` (one prop), so the drawer's
  portrait is the same robot as the roster's.
- Check: `pnpm exec tsx scripts/agent-colour-test.ts` (8 checks). It pins a hash of every
  character's draw calls on main at `fd05b69` (24 ids × 2 styles), so a moved design fails it.
- Verified: typecheck, build, crew-contract-test 35/35, agent-colour-test 8/8; the 09.2 contact
  sheet regenerates byte-identical; the draw-call logs for all 24 ids in both styles are identical
  before and after. In a headless Chrome on the mock data source (plain `vite`), picking a colour
  updated the roster chip, both portraits and the kitchen canvas in the next frame (13–28 ms), in
  both styles at 1440×1000 and 820×1000.
- Not verified: a restart of a real kitchen. The colour's persistence was exercised through the
  real `updateAgent` command and `saveConfig`/`loadConfig` in a temp folder (the value reloads
  from `.jsmhq/config.json`); no live server was started or restarted. Pathfinder mode was checked
  by test (the busy fixture's sessions take no colour), not by eye.
