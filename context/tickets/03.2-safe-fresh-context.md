# Safe fresh context: handoff → clear → orient

## Status

In Progress

## Parent Feature

`03-agent-context-tools.md`

## Blocked by

- `03.1` — reuses the send-prompt-and-await-Stop helper.

## Goal

A "Fresh context" button makes an idle agent write a handoff, clears its
context, and has it orient from the handoff and report READY.

## Context

- Read: `server/handoff.ts` (existing worker checkpoint; don't change it),
  `src/ui/drawers/CrewHeader.tsx` (L93–L125, step UI to mirror),
  `skills/handoff/SKILL.md`, and 03.1's helper.
- Relevant area: `server/handoff.ts`, `src/ui/drawers/CrewHeader.tsx`, `src/ui/drawers/AgentDrawer.tsx`, `server/hooks.ts`, `server/sessions.ts`

## Changes

- Three steps as in Feature 03, each shown as it runs. A step that fails stops
  the rest. The handoff step checks that `.jsmhq-handoff.md` is newer than the
  request.
- Clear command per harness: `/clear` (Claude) or `/new` (Codex).
- Not offered on Pathfinder workflow worker sessions, which keep Checkpoint &
  start fresh.

## Verification

- On an idle agent with a few turns: the handoff file appears, the context
  clears (the transcript shows the clear), and the reply starts with READY and
  matches the handoff.
- A forced step-1 failure (timeout) leaves the context untouched.
- `pnpm typecheck`.

## Out of Scope

- Pausing a working agent.

## Notes / Decisions

- Implementation verification (2026-11-13): 13 fresh-context scenarios use real
  Git, hooks, Inbox and snapshots with a simulated terminal/agent; all passed.
  The 11 existing summary scenarios, `pnpm typecheck`, and `pnpm build` passed.
- Native verification limitation: a disposable Claude session reached the first
  harmless fixture prompt but the account's 5-hour usage limit prevented the
  model turn. Actual Claude handoff writing, `/clear`, and READY orientation,
  plus native Codex `/new`, remain unverified. No existing live session was
  used, and no credential changes or usage-limit workaround was attempted.
