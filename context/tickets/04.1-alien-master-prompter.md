  - Low 1 fixed: the server refuses any coding agent but Claude Code for the Master Prompter, on add and on update (the whole patch is refused, with a problem message in the activity feed), and a session start refuses one as a backstop.   - Low 2 fixed: its permission mode is pinned to the documented `manual` (Claude Code 2.1.326 lists `acceptEdits, auto, bypassPermissions, manual, dontAsk, plan`). The Pathfinder launch uses it, and so does a native team's Local-mode launch. A native Sandbox launch keeps the sandbox's own VM-wide permissions.
- **Accepted limitation (Low 3), human decision 2026-11-17:** the prompter's read-only behaviour is enforced only by denying Claude Code's file-editing tools (`--disallowedTools Edit,Write,NotebookEdit`, and the same list in its settings' `permissions.deny`), plus its role instructions. It is not a read-only filesystem: Bash stays available and can write. In a Pathfinder kitchen, and a native Local-mode team, its permission mode is pinned to `manual`, so each Bash call asks the human first. A native Sandbox-mode prompter has the sandbox's own permissions inside its VM. Follow-up ticket `04.3` (prompter read-only filesystem) tracks real enforcement.
