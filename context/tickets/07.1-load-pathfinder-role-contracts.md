# Load Pathfinder role contracts into the sessions Tin & Thyme manages

## Status

In Progress

## Parent Feature

`07-pathfinder-role-wiring.md`

## Blocked by

None

## Goal

The coordinator and worker sessions receive the connected repository's real `roles/<role>.md` through
a supported instruction mechanism. Settings shows the resolved role, its source and evidence that it
loaded. All of this is proven live in an isolated Pathfinder test repository.

## Context

- Read: Feature 07's Context (the orchestrator's inspection, with file:line).
- Relevant area: `server/pathfinder.ts` (`startCoordinator`, `hookSettingsFile`, `parseBrief`, the
  worker/crew mapping), `server/agentFiles.ts`, `server/transcripts.ts`,
  `src/ui/settings/TeamSettings.tsx`, `src/ui/drawers/CrewHeader.tsx`, `src/data/types.ts`.

## Changes

- Resolve each session's Pathfinder role (coordinator → orchestrator; worker → the brief's `Role:` with its
  `Session:`), then the contract path (worktree or checkout). A missing file is a clear error.
- Load the contract text through a supported mechanism, verified against the installed Claude Code. Keep
  the brief and the skill rules unchanged. Respect named subagent definitions and report conflicts.
- Record load evidence from real session data. Show role, source path, read-only contract, and
  configured vs loaded in Settings and the crew drawer, in Pathfinder mode. Native-team ROLE.md stays
  editable.
- Tests: fixtures and mocks for resolution, missing role, conflicts and the UI state, plus a live run in an
  isolated test repository with marked contracts.

## Verification

- `pnpm typecheck`, `pnpm build`, and the new tests.
- The live run in a scratch Pathfinder repository and a test kitchen on its own port and state dir:
  - a coordinator, a developer and a fresh reviewer, each with transcript or hook evidence of its own
    marker;
  - role-appropriate behaviour, and the expected ticket skill or brief;
  - worktree resolution and missing-role handling;
  - no cross-role leak;
  - Settings matching the real sessions.
- A table: session → actual agent type → Pathfinder role → source file → load evidence → observed behaviour.

## Out of Scope

- Pathfinder's own files, 05.1, the run policy, the ticket store, push/PR/merge/publish, the live kitchen.

## Refined acceptance (human, 2026-11-12). These take precedence over Changes above where they differ

- Loading role contracts through the existing Pathfinder skills (`/ticket start` reading
  `roles/developer.md`, `/orchestrate start` reading `roles/orchestrator.md`, and so on) is a valid
  mechanism. Don't replace it just to have a second path.
- First verify, from real session evidence, whether contracts and skills are actually missing from
  sessions. Report what each session really receives today.
- Fix only demonstrated gaps in instruction loading or in configured-agent routing.
- Settings must show accurately where the contract comes from, and the load evidence available. It
  must not show "loaded" without session evidence.
- Don't inject a contract a session already loads through its skill (no duplicates), and don't
  preload unnecessary skills.
