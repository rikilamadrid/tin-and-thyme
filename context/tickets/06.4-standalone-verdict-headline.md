# A reviewer's standalone PASS is recorded as its own outcome

## Goal

A tester whose report opens with a bare `PASS` (or `FINDINGS`) line is shown as stopped and handed off with that verdict and its own result. Today it is shown as Interrupted, carrying the previous developer's DONE text. That breaks the Feature 06 criterion "A tester session that reported is not labelled Interrupted."

## Context

- Human decision, 2026-11-16: one bounded follow-up repair, as its own ticket, with regressions, independent review and normal PR delivery. Not folded into 09.3 or 06.2. 06.1 stays Complete; its repair budget was used up.
- Independent diagnosis and replay on main `9ac8a0c`: `.pathfinder/reviews/06.1-native-07.1-case/report.md` (machine-local), with `reproduce.mts` beside it.
- Root cause: `readReport` in `server/attribution.ts` accepts `VERDICT: PASS`, `PASS: …` and `Result: PASS`, but not a verdict word alone on its line. The canonical review instructions ask for exactly that: `skills/ticket/actions/review.md` ("PASS, or findings by severity") and `skills/orchestrate/engine/brief.mjs` ("Report PASS").
- Consequence: `sessionEnding` in `server/workflowState.ts` gets no verdict and falls back to the checkpoint, which is still `review`, so the outcome becomes `interrupted` and `result` inherits the developer's DONE.
- Relevant area: `server/attribution.ts`, `scripts/coordinator-attention-test.ts`

## Changes

- `readReport` recognizes a standalone `PASS` or `FINDINGS` as the report's own headline line, and nothing broader.
- Existing precedence is kept: an explicit `VERDICT:` line still wins, then the last `DONE:`/`GATE:`/`FAILED:`-style report line.
- A quoted or incidental verdict word inside prose, a quotation or a fenced code block is not taken as the report's verdict.

## Verification

- New cases in `scripts/coordinator-attention-test.ts`:
  - a review worker whose checkpoint is `State: review` with the previous developer's DONE in `Last`, and whose latest terminal handback is `PASS\n\nNo blocking findings.` followed by a tool result: both transcript settlement and Stop give stopped, handed-off, verdict PASS, its own result, and no false "worker waiting";
  - the same with a standalone `FINDINGS`;
  - false positives: PASS or FINDINGS inside prose, a quotation or a fenced code block, and a later resumed turn with no report, parse no verdict;
  - precedence: an explicit `VERDICT:` line wins over a standalone headline that disagrees with it.
- The existing report-order and stale-PASS cases still pass, and the whole attention suite passes.
- The saved native case replays as handed-off PASS: `node --import tsx .pathfinder/reviews/06.1-native-07.1-case/reproduce.mts`, where that machine-local evidence is present.
- `npm run typecheck` and `npm run build` pass.
