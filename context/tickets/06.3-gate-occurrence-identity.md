## Goal

Every gate occurrence has a durable identity in Pathfinder's own record, so the kitchen (06.1) can tell occurrences apart without timestamps or question text:
- opening a genuinely new gate creates a new occurrence ID;
- retrying the same operation reuses that ID;
- a resolution references its exact occurrence;
- reopening identical question text creates a different occurrence;
- the identity survives a restart and doesn't depend on timestamps.

## Changes

- Occurrence identity:
  - the markers become `gate-opened <key> <digest> <occurrence>` and `gate-resolved <key> <digest> <occurrence>`;
  - the occurrence is 1 + the number of existing `gate-opened` markers for that key, or another durable, non-time identity that the developer justifies;
  - it is recorded in the state file on open (e.g. `Gate-Id: <occurrence>`);
  - resolve and every retry reuse it, so writes stay idempotent per occurrence but never merge across occurrences.
- Every path that opens a gate writes the opened marker with an occurrence, including `state --set human-gate --gate`.
- Backward compatibility: old markers without an occurrence keep parsing and are treated as "no occurrence identity". Old records are never rewritten and never given an invented occurrence.
