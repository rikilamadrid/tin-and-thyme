# Bootstrap: serve a reviewed local build without disturbing running sessions

## Status

Complete

## Parent Feature

`10-in-app-delivery.md`

## Blocked by

None

## Goal

Decide, with evidence, whether a reviewed local build of Tin & Thyme can be served separately (a preview kitchen) while the current kitchen and its coordinator and worker sessions keep running. If it can, provide that preview with a clear build identity, tested before any delivery uses it. If it can't, report the exact technical blocker and the minimum one-time activation step.

## Context

- Read:
  - `server/main.ts` (startup, the instance record at `:150-154`, the port and token);
  - `server/kitchen.ts` (read only; 05.1 edits it);
  - `bin/tin-and-thyme.mjs` (read only; 05.1 edits it);
  - `docs/how-it-works.md` (kitchen records, the lock, the state directory);
  - `server/pathfinder.ts` (hook settings, read only);
  - `~/.controlroom/kitchens/` (the running kitchen's record: pid and port; never modify it).
- Relevant area: `server/preview/*`, `docs/delivery-bootstrap.md`

## Changes

- **Feasibility first.** Can a second server process start from a ticket worktree's build without touching any of these?
  - the running kitchen's instance record, lock, port and token;
  - the coordinator hook's target;
  - tmux sessions and `~/.controlroom/<kitchen>/` state.

  For example, a separate state directory and port, run in a delivery-only mode that attaches to no sessions. Name every shared resource and say how it is isolated.
- If feasible:
  - A preview mode that shows its build identity (commit SHA, tree and build time) in the UI and through a health endpoint, and refuses to run from a dirty or unreviewed tree.
  - Tested against a throwaway repository and a disposable build. Not against the live kitchen.
- If not feasible: `docs/delivery-bootstrap.md` states the exact blocker and the minimum one-time activation step: which process, which command, and what is preserved.

## Verification

- Evidence that the running kitchen's record, port, token, sessions and state are unchanged before and after a preview run.
- The preview reports its build identity.
- `pnpm typecheck` and `pnpm build` pass.

## Out of Scope

- Restarting or stopping the live kitchen.
- Changing the coordinator hook or the run policy.
- Editing `bin/`, `server/kitchen.ts` or `server/pathfinder.ts`, which 05.1 changes. If a change there is unavoidable, stop and report it.
