# Crew data contract: characters, variants, sessions

## Status

In Progress

## Parent Feature

`09-crew-lifecycle.md`

## Blocked by

## Goal

One recorded, typed contract that every downstream crew ticket builds against: character and variant IDs per role family, the crew-character ↔ session ↔ ticket relationships, the lifecycle states, the persisted crew-book shape and its migration rules.

## Context

- Read: Feature 09 (Findings and Requirements); `src/data/crew.ts` (today's characters and `assignCharacter`); `server/pathfinder.ts` `addWorker` (today's crewBook, for the migration mapping only; do not edit it)
- Relevant area: `src/data/crewContract.ts`, `docs/crew-contract.md`, `src/data/crew.ts`

## Changes

- `src/data/crewContract.ts`: exported types and constants: `CrewCharacterId` plus variants per role family (developer cooks, tester, adversary, orchestrator, helper, planner, integrator, unknown); `CrewCharacter`, `CrewSession` (session id, Pathfinder role and stage, ticket, outcome, started/ended, telemetry snapshot), `CrewState` (available, assigned, working, waiting, needs-you, unknown, finished), the crew-book file schema with a version, and allocation invariants.
- `src/data/crew.ts`: names and jobs for the new variant IDs (data only; no art).
- `docs/crew-contract.md`: the contract in prose, with the allocation rules and the migration from per-session crew.json and `config.team` rows (backup, idempotent, never deduplicate by name).
