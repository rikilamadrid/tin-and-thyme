# Crew data contract: characters, variants, sessions

## Status

Complete

## Parent Feature

`09-crew-lifecycle.md`

## Blocked by

None

## Goal

One recorded, typed contract that every downstream crew ticket builds against: character and variant IDs per role family, the crew-character ↔ session ↔ ticket relationships, the lifecycle states, the persisted crew-book shape and its migration rules.

## Context

- Read: Feature 09 (Findings and Requirements); `src/data/crew.ts` (today's characters and `assignCharacter`); `server/pathfinder.ts` `addWorker` (today's crewBook, for the migration mapping only; do not edit it)
- Relevant area: `src/data/crewContract.ts`, `docs/crew-contract.md`, `src/data/crew.ts`

## Changes

- `src/data/crewContract.ts`: exported types and constants: `CrewCharacterId` plus variants per role family (developer cooks, tester, adversary, orchestrator, helper, planner, integrator, unknown); `CrewCharacter`, `CrewSession` (session id, Pathfinder role and stage, ticket, outcome, started/ended, telemetry snapshot), `CrewState` (available, assigned, working, waiting, needs-you, unknown, finished), the crew-book file schema with a version, and allocation invariants.
- `src/data/crew.ts`: names and jobs for the new variant IDs (data only; no art).
- `docs/crew-contract.md`: the contract in prose, with the allocation rules and the migration from per-session crew.json and `config.team` rows (backup, idempotent, never deduplicate by name).

  - **M1 (09.3):** startup reconciliation is now deterministic.
    - `migrateLegacy` opens a restore pass (`book.restorePass`; `beginRestore`). Nothing is allocated while the pass is open.
    - `reconcileAfterRestore` runs once every session's liveness is decided, the reattach window included. It ends unobserved sessions first, then allocates the new and conflicted sessions oldest first against the reconciled book, with a canonical seq order.
    - Restore order no longer changes the allocation. An unseen or unconfirmed session keeps its character. A session that was overflow before the restart stays overflow (rule 6). The newest coordinator wins in any order.
  - **L1 (09.3, 09.4, 09.5):**
    - `FAMILY_COLOR` is the public role-colour map. 09.3 replaces `ROLE_COLOR` with it. Orchestrator keeps the shipped `#ff77a8` so the coordinator stays distinctive. Needs-you is never shown by body colour.
    - `crewColor` resolves the drawn colour, and `CrewCharacterView.accent` is never null.
    - `crewColorProblem` refuses the needs-you pinks (agentPalette[0] included) and the unknown grey on characters other than `unit`.
    - `customizeCharacter` and `retireCharacter` are the only character writers. 09.4 calls them through a 09.3 endpoint. Basil can't be retired.
  - **L2 (09.3):** 09.3 stops writing `crew.json` and `sessions.json` when it adopts the book. The legacy files are frozen migration inputs (rules 2 and 6 agree), so later starts append no migration entry and write no backup.
  - **L3:** `kind` is never filled on restore. crew.json and sessions.json are only ever written for brief workers, so every migrated session is a `worker`. The doc's fill list was corrected.
  - **L4 (09.5):** `crewFloorChanges(prev, next)` is the transporter trigger. It compares two snapshots of one connection, and the first snapshot after a (re)connect or restart gives nothing, so arrivals are never replayed. Overflow is a session with no robot, so there is no off-floor overflow case.
  - **L5:** "≥3 variants per supported family" is read as the parallel families, in line with Feature 09's "parallel roles get recognizable variants". Orchestrator stays a single Basil ("stays distinctive"). Planner and integrator never run in parallel in this kit.
  - **Nit:** the reconcile test title now gives the tiebreak in the right order.
  - **Tests:** `scripts/crew-contract-test.ts` now has 35 checks: the original 27, plus every one of the 40,320 restore orders of the restart scenario, the reviewer's case, incomplete observation, coordinator order, a 400-run fuzz with restarts in two random orders, colours, the transporter, and kind.
