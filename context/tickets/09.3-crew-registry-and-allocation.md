# Persistent crew registry, session records and safe migration

## Status

In Progress

## Parent Feature

`09-crew-lifecycle.md`

## Blocked by

- `09.1` — builds against the crew contract

## Goal

The server keeps persistent crew characters and disposable session records, allocates characters by the contract's rules, and stops adding a `config.team` row per session. Existing kitchens migrate without losing ids, outcomes, ticket links or transcripts.

## Context

- Read: `docs/crew-contract.md`; `server/pathfinder.ts` (`addWorker`, `crewBook`, `endBook`, restore from transcripts)
- Relevant area: `server/crew.ts`, `server/pathfinder.ts`

## Changes

- New `server/crew.ts`: registry, allocation (reuse an available compatible character first; distinct characters for concurrent sessions; bounded visible crew with overflow), persistence in `~/.controlroom/<key>/`, and a versioned migration with a backup that is safe to retry.
- `server/pathfinder.ts`: a minimal hook. `addWorker` records a session against an allocated character instead of pushing an `AgentConfig`. Publish crew and sessions on the snapshot.
- Never resume a conversation when a character is reused.

## Verification

- Unit tests: concurrent same-role sessions get distinct characters; reuse after finish gets a fresh session; ids are stable across restart; migrating a copy of a real crew.json/team snapshot is lossless and idempotent, with a backup.
- `pnpm typecheck` and `pnpm build` pass.

## Out of Scope

- Settings UI (09.4); galley placement (09.5); attention logic (06.1).
