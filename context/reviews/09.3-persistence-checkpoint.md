## Unresolved decision

The approved contract defines a crew session ID as the Claude subagent ID and forbids an ended session becoming live. The existing runtime deliberately supports observing resumed turns under that same Claude ID. An integration must represent these honestly without erasing earlier outcomes or claiming a fresh conversation.

The coordinator has asked whether to permit explicitly linked continuation occurrences: preserve the original Claude ID and transcript, immutable previous outcome, deterministic occurrence identity based on recorded evidence, and label the occurrence as the same conversation. No such amendment or runtime behavior is implemented here. Repeated hooks, late bookkeeping and restart must not mint duplicate occurrences; an ambiguous hook-only resume must remain explicit rather than fabricate a boundary.

## Bounded persistence repair round 1

Independent checkpoint review of `fef7636c46153f1b15c0f28d1193546d10487366` found three Medium issues. This repair addresses those findings only; runtime integration and the identity decision remain pending.

- M1: file reads now distinguish `ENOENT` from permission/I/O failures. An unreadable valid book fails closed with its path and error code; it is not quarantined or replaced. The regression uses a real temporary file with denied read permissions, verifies `EACCES`, restores permissions, and confirms its original history reloads.
- M2: every legacy crew/ending entry is validated before any quarantine, backup or migration adoption. Malformed input identifies its path, session ID and invalid field and leaves original bytes and any existing book untouched. Optional old `next`/`result` fields normalize to null. Migration and save also check that the resulting book satisfies the same loader validation. Coverage includes malformed outcome, timestamp, result/next, verdict, occurrence, null entry and missing/wrong crew fields; a valid migration retains later sessions across restart.
- M3: a newly imported ending or a fill of an existing null ending copies the entire validated outcome, including verdict, occurrence, consumed and additional evidence. Existing non-null outcomes remain immutable. Replay preserves the full fill and does not create another migration.
