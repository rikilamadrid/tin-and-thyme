### Accepted limitation (Low 3)

Human decision, 2026-11-17: for 04.1 the prompter's read-only behaviour is enforced only by denying Claude Code's file-editing tools (`--disallowedTools Edit,Write,NotebookEdit` and the same `permissions.deny`) plus its role instructions. It is not a read-only filesystem. Bash stays available and can write. In a Pathfinder kitchen, and in a native Local-mode team, its permission mode is pinned to `manual`, so each Bash call asks the human first. A native Sandbox-mode prompter has the sandbox's own permissions inside its VM. Follow-up ticket `04.3` (prompter read-only filesystem) tracks real enforcement. UI and code wording no longer presents "never edits files" as a guarantee; the role still tells the model not to edit.
